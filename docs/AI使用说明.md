## 四、典型使用过程

1. 先确定技术栈、表结构、分层方式和模块顺序；
2. 每次只做一个模块，先实现最小可运行版本；
3. 在 IDEA 中运行，用浏览器、curl 和 MySQL 查询验证；
4. 出错时把完整错误信息交给 AI，要求给出最小修改；
5. 自己修改并再次验证，确认后再进入下一个模块；
6. 关键代码在注释中标注 AI 参与情况；
7. 每个模块的提示词摘要和验证记录写入 `docs/开发日志.md`。

## 五、AI 生成后由本人修改的典型问题

| 问题 | 现象 | 处理 |
|---|---|---|
| SQL 拼接缺少空格 | `activeFROM product` 导致 500 | 改为文本块 SQL |
| `OrderService` 缺少 `@Service` | 启动时找不到 Bean | 补注解并重启 |
| `OrderView` 字段拼写错误 | 模板报 `order` 属性不存在 | 改为 `order` |
| Thymeleaf 表单嵌套 | `<p>` 内放 `<form>` 导致解析异常 | 改为 `<div>` 并把表单移出 |
| 角色修改后仍 403 | Session 中还是旧权限 | 退出后重新登录 |
| 中文表单 400 | curl 按 GBK 发送 | 浏览器 UTF-8 验证，接口统一 UTF-8 |
| 邮件本地演示 | 未配置 SMTP | 本地 `.eml` 演示，部署时实测 SMTP |

这些问题都有运行记录和修改过程，说明 AI 输出经过本人审查，不是直接照搬。

## 六、验证方式

- 编译：`./mvnw -q -DskipTests compile`
- 运行：`./mvnw spring-boot:run`
- 浏览器：注册、登录、商品浏览与搜索、购物车、下单、订单状态、后台管理、销售报表
- 数据库：`SHOW TABLES`、`SELECT` 核对库存、订单、发件箱和统计结果
- 功能测试用例：[测试用例.md](测试用例.md)
- 开发过程记录：[开发日志.md](开发日志.md)

## 七、敏感信息与仓库安全

- 数据库密码保存在 `config/application-local.properties`，该目录已在 `.gitignore` 中排除；
- 演示邮件保存在 `data/`，同样不提交；
- 仓库中不包含数据库密码、SMTP 授权码、云服务密钥；
- 报告和公开 README 中不写真实密码；
- 如密码曾在对话、日志或截图中临时出现，应立即更换相关密码。
