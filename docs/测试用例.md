# 功能测试用例

测试环境：Windows 10、JDK 25（编译目标 17）、Spring Boot 4.1.1、MySQL 8.4.11、Edge 浏览器。

说明：本项目当前以手工接口与浏览器测试为主；尚未编写 MockMvc 自动化集成测试。下表“结果”一栏区分已实测与待补测项。

| 编号 | 模块 | 测试步骤 | 预期结果 | 结果 |
|---|---|---|---|---|
| TC-01 | 注册 | 填写姓名、邮箱、8 位以上密码，两次密码一致 | 302 跳转登录页，提示注册成功并预填邮箱；`shop_user` 新增记录，密码为 BCrypt 哈希 | 通过 |
| TC-02 | 注册 | 使用已注册邮箱再次注册 | 返回注册页，提示“该邮箱已注册” | 通过 |
| TC-03 | 注册 | 两次密码不一致 | 返回注册页，提示“两次输入的密码不一致” | 通过 |
| TC-04 | 登录 | 使用正确邮箱和密码登录 | 302 跳转首页，右上角显示邮箱和退出 | 通过 |
| TC-05 | 登录 | 使用错误密码登录 | 跳转 `/login?error`，提示“邮箱或密码错误” | 通过 |
| TC-06 | 权限 | 未登录访问 `/hello` | 重定向到 `/login` | 通过 |
| TC-07 | 商品查询 | 搜索 `Java`、筛选 `教材`、组合无结果条件 | 结果数量分别为 1、2、0，空结果有提示 | 通过 |
| TC-08 | 购物车 | 登录后点击“加入购物车” | 首页提示“已加入购物车”，`cart_item` 新增/累加数量 | 通过 |
| TC-09 | 购物车 | 修改数量、移除商品 | 小计和合计同步变化，移除后记录删除 | 通过 |
| TC-10 | 下单 | 填写收货信息提交订单 | 生成 `orders` 与 `order_item`，库存减少，购物车清空 | 通过 |
| TC-11 | 下单回滚 | 购物车两件商品，其中一件库存改为 0 后提交 | 提示库存不足，不生成订单，另一件库存不变 | 通过 |
| TC-12 | 重复提交 | 结算页快速提交两次 | 第二次提示“订单已提交，请勿重复操作” | 已实现，建议补测 |
| TC-13 | 付款 | 对待付款订单点“模拟付款” | 状态变为 PAID，`paid_at` 写入时间 | 通过 |
| TC-14 | 取消订单 | 取消待付款订单 | 状态变为 CANCELLED，商品库存恢复 | 通过 |
| TC-15 | 取消校验 | 对已付款订单点“取消” | 提示“只能取消自己的待付款订单” | 通过 |
| TC-16 | 后台发货 | 管理员对已付款订单填写物流单号发货 | 状态变为 SHIPPED，记录物流单号 | 通过 |
| TC-17 | 发货校验 | 对未付款或已取消订单调用发货 | 提示“只有已付款订单才能发货” | 通过 |
| TC-18 | 确认收货 | 顾客对已发货订单点“确认收货” | 状态变为 COMPLETED | 通过 |
| TC-19 | 后台权限 | 普通顾客访问 `/admin/orders` | 返回 403 | 通过 |
| TC-20 | 邮件 | 发货后检查发件箱和 `data/mail` | `mail_outbox` 为 SAVED，生成 `.eml`，内容含订单号和物流单号 | 通过 |
| TC-21 | 邮件重试 | 将邮件状态改为 FAILED 后点“重试邮件” | 状态恢复为 SAVED，不产生重复订单 | 通过 |
| TC-22 | 真实 SMTP | 配置 QQ 邮箱授权码后发货 | 收件邮箱实际收到发货通知 | 待部署环境实测 |
| TC-23 | 商品管理 | 新增、编辑、下架、上架商品 | 前台可见性随之变化，价格按分存储 | 通过 |
| TC-24 | 销售统计 | 打开 `/admin/stats` | 销售额、订单数、客单价、趋势、排行、分类占比正确 | 通过 |
| TC-25 | 越权订单 | 用户 A 尝试付款/取消用户 B 的订单 | 影响 0 行并提示无权限 | 已实现，建议补测 |
| TC-26 | 并发下单 | 两个请求同时抢最后一件库存 | 仅一个成功，库存不小于 0 | 已实现条件更新，建议补测 |
| TC-27 | 商品删除 | 下架已售商品后查看历史订单 | 历史订单商品名和单价快照不变 | 设计保证，建议补测 |
| TC-28 | 商品删除 | 删除无历史订单的商品；再删除有历史订单的商品 | 前者从后台和数据库消失；后者提示已有历史订单，不能删除 | 通过 |

## 建议补测项

1. TC-12 重复提交：在结算页连续点击两次提交。
2. TC-25 越权订单：准备两个顾客账号，直接构造另一个订单 ID 的 POST 请求。
3. TC-26 并发下单：用两个线程同时提交最后一件库存。
4. TC-22 真实 SMTP：部署后配置授权码实测。
